🏢 Agentic SOC

1. RSAC 2026 上的 Agentic SOC 三巨头：CrowdStrike、Cisco/Splunk、Palo Alto Networks 同时发布 Agent 化 SOC 工具

背景：2026 年的 RSAC 被与会者称为「Agent 之年」——三大安全巨头同时发布了各自的第一代 Agentic SOC 产品，标志着 SIEM/SOAR 行业正式进入 AI Agent 时代。

技术要点：

  • CrowdStrike Falcon 升级：将端点和 EDR 定位为 AI 安全控制面。发布了 EDR AI Agent（自动分析端点威胁并生成响应建议）和 AI Security Posture Management（AI 安全态势管理，监控企业内部 AI Agent 的行为权限和数据访问）。CEO George Kurtz 在 keynote 中指出：最快记录的攻破时间已降至 27 秒——人的响应速度完全跟不上，Agent 化防御是唯一选择。

  • Cisco/Splunk → 六款专用安全 Agent：Cisco 和 Splunk 联合发布了嵌入 Splunk Enterprise Security 的六款 AI Agent——Detection Builder（自动生成检测规则）、Triage（告警分级筛选）、Guided Response（引导式响应）、SOP（标准操作流程自动化）、Malware Threat Reversing（恶意软件逆向分析）、Automation Builder（自动化工作流构建）。这些 Agent 直接运行在 SIEM 内部，无需额外的编排工具。

  • Palo Alto Networks Prisma AIRS 3.0：全新一代 AI 安全平台，主打「Agentic AI for Coordinated Defense」——多个安全 Agent 可以相互协作，一个 Agent 发现的威胁自动通知其他 Agent 开启对应防护。同时发布了 Shadow AI 治理功能（发现企业内部未经批准的 AI Agent 使用）。

对安全 Agent 领域的启发：RSAC 2026 标志着安全 Agent 从「实验性项目」进入「产品化阶段」。三大巨头的路径不同（CrowdStrike 端点切入、Cisco/Splunk SIEM 内置、Palo Alto 平台化），但共识明确——SOC 的 Agent 化不是可选项，而是应对 27 秒攻破窗口的唯一可行方案。

2. VentureBeat 深度分析：Agentic SOC 的「行为基线缺口」——三巨头产品都没解决

背景：VentureBeat 在 RSAC 2026 现场发布的深度分析指出，尽管 CrowdStrike、Cisco 和 Palo Alto 都发布了 Agentic SOC 工具，但所有人都回避了一个关键问题——AI Agent 的行为基线是什么？

技术要点：

VentureBeat 的分析将当前安全 Agent 方案分为两类：

  • 方案 A（SIEM 内置 Agent，Cisco/Splunk 路线）：Agent 工作在 SIEM 内部，可以访问所有日志和告警，优点是上下文丰富，缺点是 Agent 自身的行为（它访问了哪些数据、调用了哪些 API）缺乏审计——谁在监控监控者？

  • 方案 B（上游管道检测，CrowdStrike 路线）：Agent 在端点层面检测威胁，优点是靠近攻击来源，缺点是缺乏全局视角。

共同缺口：没有方案为 Agent 自身建立行为基线——正常运行的 Agent 应该访问哪些数据、不应该访问哪些、Agent 之间的通信是否正常。Anthropic 在 RSAC 2026 上展示的「Constitutional AI for Agents」方案试图解决这个问题（将安全策略编码为 Agent 的行为宪法），但尚未集成到任何商业产品中。

对安全 Agent 领域的启发：安全 Agent 的「元安全」（Meta-Security——保护安全工具自身的安全）是一个尚未被充分解决的新领域。当 SOC 完全依赖 Agent 进行威胁检测时，Agent 自身被攻陷的后果比传统工具更严重。

3. Databricks Lakewatch SIEM：数据湖公司跨界进入 SIEM 市场，与 Anthropic Claude 集成

背景：Databricks 在 RSAC 2026 上发布了 Lakewatch SIEM 产品，这是 Databricks 通过收购两家安全公司并与 Anthropic 合作推出的首个 SIEM 产品。

技术要点：Lakewatch SIEM 将 Databricks 的数据湖架构应用于安全日志——安全团队可以在同一个平台上存储、查询和分析安全数据，无需将日志导入专门的 SIEM 存储。与 Anthropic Claude 的集成提供 AI 驱动的告警关联和自然语言查询接口（用英语问「过去 24 小时有没有异常登录行为？」即可获得分析结果）。定价基于存储量（$0.10/GB/月），远低于传统 SIEM 的按 ingest 量定价。

对安全 Agent 领域的启发：数据湖 + LLM 的 SIEM 新范式正在挑战 Splunk/Elastic 的传统 SIEM 架构。Agent 在这里的角色是「自然语言接口 + 告警关联引擎」——安全分析师不再需要学习 SPL（Splunk 查询语言）或 EQL，直接用自然语言与 SIEM 交互。

⚔️ 攻防技术

4. AI Agent 相关数据泄露平均成本达 $470 万，提示注入影响已超三分之一的活跃 Agent

背景：Dark Reading 和多个行业报告在 2026 年第二季度发布的数据显示，AI Agent 安全已经从「学术担忧」变成了「可量化的企业风险」。

技术要点：

  • AI Agent 相关数据泄露的平均成本为 $470 万/次（高于传统数据泄露的 $445 万——IBM 2025 年数据）
  • 有控制的测试显示，自主 Agent 可在 2 小时以内 完成企业环境的横向移动
  • 提示注入（Prompt Injection） 已经影响了超过三分之一的已部署 Agent——这甚至不是在 2024 年才有标准命名的攻击手法
  • 48% 的网络安全专业人士将 Agentic AI 列为 2026 年最危险的攻击向量

对安全 Agent 领域的启发：提示注入的广泛影响表明，Agent 的「输入净化」是当前产品中最薄弱的环节。大多数 Agent 框架（LangChain、AutoGPT、CrewAI）的默认配置对恶意提示几乎没有防御能力。企业部署 AI Agent 前必须建立 Agent 的输入验证层。

🔧 框架与工具

5. Anthropic 在 RSAC 2026 展示「Constitutional AI for Agents」——将安全策略编码为 Agent 行为宪法

背景：Anthropic 在 RSAC 2026 上展示了一项新研究——将 Constitutional AI（宪法 AI，用于让 AI 模型遵循行为准则）的概念扩展到 AI Agent 领域。

技术要点：Anthropic 的「Constitutional AI for Agents」方案将企业的安全策略（如「不要访问包含 PII 的数据库」「不要修改生产环境的配置」「所有需要数据删除的操作必须经人工确认」）编码为 Agent 的行为宪法。Agent 在执行每个操作前，内部推理该操作是否符合宪法——如果违反，Agent 自动拒绝执行并报告。与传统的 RBAC（基于角色的访问控制）相比，Constitutional AI 的约束不是静态的权限列表，而是语义级别的行为约束——可以处理「这个操作的上下文是否安全」这类需要理解语义的边界情况。

对安全 Agent 领域的启发：Constitutional AI for Agents 可能是解决「Agent 行为基线缺口」（见第 2 条）的一个重要方向——不是记录 Agent 做了什么（审计日志），而是在 Agent 做之前就阻止它做不该做的事。但该方案目前仍是研究阶段，尚无商业化产品集成。

📄 论文与报告

6. Darktrace《2026 年 AI 网络安全状况报告》：92% 的安全专业人士对 AI Agent 表示担忧

背景：Darktrace 发布年度《State of AI Cybersecurity Report 2026》，对 1500 名网络安全专业人士进行调研，揭示了 AI Agent 在企业中快速普及带来的安全隐忧。

核心发现：

  • 92% 的安全专业人士对 AI Agent 在工作场所的广泛使用表示担忧（较 2025 年的 76% 显著上升）
  • 78% 的受访者所在组织已在至少一个业务功能中使用生成式 AI
  • 76% 对在企业中集成 AI Agent 的安全影响表示担忧
  • 报告特别指出：AI Agent 的行为理解（如何知道 Agent 在做什么、为什么这么做）和管理（如何控制 Agent 的权限和访问范围）是 2026 年最高优先级的两个安全课题
  • AI Agent 被视为「一等身份」（First-Class Identities）——需要像对待员工身份一样进行持续的监控和治理

对安全 Agent 领域的启发：Darktrace 报告的数据量化了安全社区对 AI Agent 的集体焦虑。最值得注意的观察是「AI Agent 作为一等身份」——这意味着 IAM（身份与访问管理）系统需要扩展到 Agent 身份生命周期管理。AI Agent 应该有自己的 Service Account、权限范围和操作审计日志，就像每个员工一样。

🌐 行业动态

7. 英国 CMA 要求 Google 给内容发布者更多 AI 内容使用控制权

背景：英国竞争与市场管理局（CMA）裁定 Google 必须为内容发布者提供工具，允许他们选择退出其内容被用于 AI 生成搜索特性和模型训练。

技术要点：裁定要求 Google 提供：① 发布者级别的 opt-out 机制（不是整个网站的 robots.txt，而是细粒度的按页面/按内容类型选择退出）；② 发布者可以看到自己的内容是否被用于 AI 训练；③ Google 需要定期报告 AI 内容使用的透明度数据。这标志着监管部门开始认真对待 AI 训练数据权力问题。

对安全 Agent 领域的启发：监管对 AI 内容使用的介入将影响安全 Agent 的数据来源合规性——如果安全 Agent 依赖的威胁情报来自受版权保护的内容，Agent 的运营者可能需要承担合规责任。建议安全团队在部署 AI Agent 时，记录 Agent 所有的数据来源以便应对合规审计。

8. CrowdStrike Spring 2026 发布：AI Agent 安全治理 + 端点成为 AI 控制面

背景：CrowdStrike 的 Spring 2026 发布将重点放在了 AI Agent 安全治理和端点的控制面角色上。

技术要点：CrowdStrike 更新的核心逻辑是——AI Agent 在端点上运行、通过端点访问企业数据、在端点产生行为痕迹。因此端点是管理 AI Agent 安全的理想「控制面」。新增功能包括：AI Agent 发现（自动发现端点上运行的 AI Agent）、AI Agent 权限管理（限制 Agent 可以访问的文件/网络/API）、AI Agent 行为审计（记录 Agent 的所有操作）。Shadow AI 治理方面，可以检测员工使用未经批准的 AI 工具（如个人账号的 ChatGPT）。

对安全 Agent 领域的启发：端点作为 AI 安全控制面的思路是务实的——与其试图在网络层面拦截 AI 流量（加密/动态 IP 使这越来越困难），不如在端点层面管理 AI Agent 的行为。CrowdStrike 的这个方向与其他安全厂商的「网络层 AI 检测」策略形成对比，值得关注哪种方法在生产环境中更有效。
