Agentic SOC

1. RSAC 2026：Agentic AI 安全成为全场核心议题

背景：2026 年 4 月/5 月举办的 RSA Conference 2026（RSAC）上，Agentic AI 安全从「小众专题」演变为「全场核心话题」。多家安全巨头同时推出面向 AI Agent 的原生安全产品。

技术要点：

  • RSAC 2026 标志着行业共识形成：传统安全工具是为人类操作软件设计的，无法保护自主行动的 AI Agent
  • 三大安全厂商（CrowdStrike、Palo Alto Networks、SentinelOne）同时在 RSAC 上发布 AI Agent 安全产品
  • Non-Human Identity（NHI）安全问题首次成为 RSAC 五大议程之一——AI Agent 在凭证和访问权限方面引入全新攻击面
  • CRN 评选的 RSAC 2026「最酷 AI 安全产品」中，绝大部分与 Agentic AI 直接相关

启发：2026 年标志着「AI Agent 安全」从概念验证进入规模化产品阶段。与 2025 年不同，2026 年不再是「为什么需要保护 AI Agent」的讨论，而是「用谁的产品保护」的选型阶段。安全团队需要在 2026 年下半年完成 Agent 安全产品的评估和试点。

2. Palo Alto Networks 发布 Prisma AIRS 3.0：Agentic AI 运行时安全平台

背景：Palo Alto Networks 在 RSAC 2026 上发布了 Prisma AIRS 3.0（AI Runtime Security），定位为专为 Agentic AI 设计的端到端安全生命周期平台。

技术要点：

  • Agent 发现与清单：自动发现组织内部运行的所有 AI Agent，包括影子 AI（Shadow AI）——员工自行部署的未授权 Agent
  • 运行时保护：实时监控 Agent 的行为——访问了哪些数据、调用了哪些工具、产生了哪些输出——一旦发现异常行为自动阻断
  • 身份与授权：为每个 Agent 分配最小权限身份，Agent 的凭证管理独立于人类用户
  • 模型/Agent/连接三维可视：跨云、SaaS、端点全面展示 AI Agent 资产图谱
  • 与 Palo Alto NGFW 和 Prisma Cloud 深度集成

启发：Prisma AIRS 3.0 尝试填补「Agentic AI Security」的分类空白——这是一个全新的安全品类。与 2025 年的 CSPM（云安全态势管理）类似，AIRS 3.0 可能成为企业 AI 安全的事实标准。但运行风险是：Palo Alto 能否在 Microsoft、CrowdStrike 和云原生创业公司定义品类之前快速占领市场。

3. CrowdStrike 发布 Falcon AI Runtime Protection 和 Shadow AI Discovery

背景：CrowdStrike 在 RSAC 2026 上发布了三个面向 AI 安全的新产品线：Falcon AI Runtime Protection、Shadow AI Discovery 和 AI Detection & Response（AIDR）。

技术要点：

  • Falcon AI Runtime Protection：扩展端点检测能力到 AI 运行环境——监控 LLM 调用、Agent 行为、训练数据访问。检测模型投毒、prompt 注入、数据泄露等 AI 特有攻击
  • Shadow AI Discovery：自动发现端点上运行的所有未经批准的 AI 工具和 Agent——员工可能在使用影子 AI，包括浏览器中的 AI 插件、本地的 Agent 框架、未注册的 LLM 调用
  • AIDR for Endpoint：AI 驱动的端点检测与响应，结合 Falcon 的实时遥测数据和 AI 行为分析
  • CrowdStrike CEO George Kurtz 表示：「端点是 AI 被访问和使用的地方，因此端点安全重新成为安全执行的核心焦点」

启发：CrowdStrike 的战略是将端点作为「AI 安全执行点」——因为无论 AI Agent 在哪运行，最终必然在端点上被使用。Shadow AI Discovery 是 2026 年最迫切的安全需求——大量员工已经在工作中使用个人 AI 工具，安全团队对此完全无感知。

4. Fortinet 发布 FortiSOC：统一云原生 SOC 平台 + Agentic AI

背景：Fortinet 在 RSAC 2026 前后发布了 FortiSOC，一个统一的云交付 SOC 平台，内置 Agentic AI 能力。同时 FortiSOAR 8.0.0 正式引入 Agentic AI 框架支持。

技术要点：

  • 统一平台：将 SIEM、SOAR、威胁情报、网络检测与响应（NDR）整合为单一云平台
  • 19 个预建 AI Agent：FortiSOAR 8.0.0 内置 19 个 AI Agent，可自主执行调查、分类、取证和响应
  • FortiGuard 威胁情报驱动：Agent 使用 FortiGuard Labs 的实时威胁情报进行决策
  • 适用所有规模：从基础 SOC 能力到企业级高级 SOC，同一平台可扩展
  • 零信任集成：Agent 行为监控 + 最小权限原则，每个 Agent 的访问权限严格受限

启发：Fortinet 的 FortiSOC + FortiSOAR 8.0 是「传统 SOAR 厂商拥抱 Agentic AI」的典型案例。不是从零构建 AI Agent，而是在成熟的编排/自动化平台中嵌入 Agent 层。这种渐进式路径对已部署 SOAR 的企业来说迁移成本最低。

攻防技术

5. SentinelOne 与 Palo Alto 达成技术联盟，联合 AI Agent 安全

背景：RSAC 2026 上，SentinelOne 宣布与 Palo Alto Networks 建立新的技术联盟伙伴关系，合作聚焦于 AI Agent 安全领域的联合能力。

技术要点：

  • 两家端点安全巨头联合开发 AI Agent 的安全检测和响应标准
  • SentinelOne 的 Purple AI 安全分析平台与 Palo Alto Prisma AIRS 数据互通
  • 联合工单编排：一个平台上检测到的 AI Agent 威胁可自动触发另一个平台的响应动作
  • 目标：建立跨厂商的 AI Agent 安全互操作标准

启发：当两大安全巨头选择联合而非竞争时，说明 AI Agent 安全市场的规模足够大，单一厂商无法完全覆盖。这种合作可能催生「AI Agent 安全互操作协议」——类似 OpenTelemetry 在可观测性领域的标准化作用。

6. Anthropic 与 Databricks 合作打造 AI 驱动的 SIEM 产品「Lakewatch」

背景：Anthropic 宣布「将前沿网络安全能力提供给防御者」，同时 Databricks 在 RSAC 上发布了基于其数据平台的 SIEM 产品「Lakewatch」。

技术要点：

  • Databricks Lakewatch 是 Databricks 通过收购多家公司 + 与 Anthropic Claude 合作打造的 AI 原生 SIEM
  • Lakewatch 利用大模型的自然语言理解能力进行威胁狩猎——安全分析师可以用自然语言查询安全事件
  • 底层数据平台是 Databricks 的 Lakehouse，直接在数据湖上进行安全分析
  • 与 Anthropic 合作：Claude 模型作为安全分析 Agent 的内核，负责告警分类、上下文推理、响应建议生成

启发：云数据平台公司（Databricks、Snowflake）进入安全市场是 2026 年的新趋势。他们不构建传统 SIEM，而是利用原有数据平台 + AI Agent 层提供「AI 原生 SIEM」。这对传统 SIEM 厂商（Splunk、QRadar）构成实质性威胁。

框架与工具

7. AgentSOC：多层级 Agentic AI SOC 自动化的学术框架

背景：2026 年 IEEE 会议上发表的论文《AgentSOC: A Multi-Layer Agentic AI Framework for Security Operations Automation》，提出了一个层级化的 Agentic SOC 理论框架。

技术要点：

  • 四层架构：感知层（告警归一化）→ 推理层（攻击意图推测）→ 规划层（处置方案生成）→ 执行层（策略合规响应）
  • 混合推理：结合符号推理（rule-based）和神经网络推理（LLM-based），而非纯端到端 LLM
  • 风险感知规划：Agent 生成处置方案时会评估「安全效能 vs 运营影响」的平衡
  • 在 LANL 认证数据集上进行了概念验证

启发：学术框架的价值在于定义了 SOC Agent 的「标准架构」——四层抽象与人类的 Tier1→Tier2→Tier3 分析师分层天然对齐。任何构建 SOC Agent 的产品都可在该框架中找到自己的定位。

8. Torq 发布 Hyperautomation + Agentic AI SOC 指南

背景：安全自动化平台 Torq 在 2026 年发布《Agentic AI & Hyperautomation: Your SOC Guide for 2026》，提出从「SOAR」到「Hyperautomation」再到「Agentic AI SOC」的演进路径。

技术要点：

  • 40% 的安全告警未被调查——传统 SOAR 无法跟上告警量增长
  • 超自动化（Hyperautomation）：在 SOAR 基础上增加 AI 驱动的决策层，不再依赖预定义的 playbook
  • Agentic AI SOC：AI 充当数字分析师，24/7 处理告警，仅在需要战略决策时升级给人类
  • 最佳起步场景：钓鱼邮件分类——是高信任度的 AI 自动化入门场景
  • 从「人工分类→AI 辅助→AI 授权→AI 自主」四个成熟度阶段

启发：Torq 的成熟度模型对安全团队有实际参考价值：不是一步到位到全自动 SOC，而是从高确定性、低风险的场景（钓鱼邮件分类）开始逐步扩展 Agent 的决策范围。

论文与报告

9. Darktrace《2026 AI 安全现状报告》：92% 安全专家担忧 AI Agent 安全

背景：Darktrace 发布年度《State of AI Cybersecurity 2026》报告，调查了超过 1,500 名网络安全专业人士。

关键发现：

  • 92% 的安全专业人士对 AI Agent 在企业中的使用感到担忧
  • 87% 观察到更多 AI 驱动的攻击——更快、更个性化、更难检测
  • 76% 担心将 AI Agent 集成到组织中的安全影响
  • 47% 的安全高管「非常担心」AI Agent 直接访问敏感数据和关键业务流程
  • 只有不到 30% 的企业有明确的 AI 安全使用政策
  • AI 驱动的身份攻击是最常被报告的 AI 安全事件类型

启发：92% 这个数字意味着 AI Agent 安全的担忧已成为共识，但不到 30% 的企业有应对政策——这就是「意识先行、行动滞后」的经典安全缺口。2026 年下半年，预计将看到更多企业从「担忧」转向「行动」，推动 AI Agent 安全产品的采购潮。

来源

10. NeuralTrust《2026 AI Agent 安全现状报告》：CISO 的风险优先级正在从「假设性」转向「操作性」

背景：NeuralTrust 发布《The State of AI Agent Security 2026》报告，对企业集成 AI Agent 的安全风险进行了全面调研。

关键发现：

  • Top 3 风险：数据泄露（62%）、Prompt 注入/对抗操纵（58%）、未授权操作/过度自治（47%）
  • 企业对 AI Agent 安全的成熟度分为四个阶段：初生期（无控制，25%）→ 意识期（有策略，35%）→ 结构化期（有工具，25%）→ 主动期（持续改进，15%）
  • 78% 的企业已在至少一个业务部门使用生成式 AI
  • NHI（Non-Human Identity）安全问题正在加速——AI Agent 引入的新身份数量远超人类用户

启发：CISO 的风险优先级从「假设性担忧」转向「操作性风险」是一个关键转折点——意味着安全预算的分配正在从「评估工具」转移到「部署工具」。四阶段成熟度模型为安全团队提供了清晰的自我定位和路径规划工具。
